## From task 3.8 (offline verifier CLI)

1. **3.4 `services/evidence/src/tsa.ts` `verifyTimestampToken` ignores the CMS signature result.** It calls `sd.verify({ signer: 0, checkChain: false, extendedMode: true })`; in extended mode pkijs returns `{ signatureVerified }` and does not throw, so the `catch` that returns `SIGNATURE_INVALID` never runs. Evidence: flipping any one byte of the signature value of a token built by the local test authority was still accepted (probe: 287 of 946 single-byte flips accepted; 0 of the signature bytes with the CLI's extra check). Fix: use `(await sd.verify(...)).signatureVerified`. The CLI checks it itself (`tools/verifier-cli/src/log.ts`, `cmsSignatureValid`) until this is fixed, then that function can go.
2. **3.4 same function:** flips inside the certificates carried by the token (bytes ~490 to ~860 of the local token) are also accepted. Not analysed further; needs a review that the chain really binds the signer certificate to the trusted root (try a forged certificate with the root's subject name signed by another key).
3. **3.4 bundle is missing data the arbitrator needs for three DESIGN 8.8 checks.** The CLI reads these optional files and reports "not verified" (a failure with `--require-complete`) when they are absent:
   - `release/gate-input.json`: the whole `ReleaseInput` of the release gate as JSON, every `Uint8Array` as `{"$bytes": "<base64>"}`. Needed to rerun `checkRelease` (signed contract, ops bindings, bar records, credentials, attestations). The builder today writes only the pieces (`signed-contract/`, `ops/`, `bar/`, `attestations/`) and not the ledger snapshot (deal wallet account and objects, mint transaction blob, credentials, ops accounts, ledger headers) or the sealed deal data.
   - `zk/reverify/<side>-<stage>.json`: `{ set: {request, proofs, queryResult}, verification, loaders, bodies: {"manifest/<v>" | "circuit/<hash>": <file text>} }`. Needed for offline ZK re-verification. Today `zk/proofs/*.json` holds only the public proof bytes and `registry_roots` (hashes of the loader files, not the files), and the full proof set is the open question 2 of 1.17 / OD-25.
   - Clause proofs a party chooses to include: `contract/files/<name>.clause-proof.json` as `{index, size, salt (hex), clause (base64), path (hex[])}`.
4. **3.4 `assets/verify.ts`** (item 12) is a manifest-only script. The CLI replaces it: ship `tools/verifier-cli` `dist/verify.js` (built by `node scripts/bundle.ts <out>`) inside the bundle as `verify.js`, and name it in README.txt.
5. `verifyTimestampToken` lives in `tsa.ts` next to the HTTP client; the CLI bundle therefore carries the client code (unused, no sockets opened). Moving the verifier into `@legx/core` (for example `core/tsaToken.ts`) would let the CLI import only core, as 3.8 specifies.
6. `pnpm-workspace.yaml`: added `esbuild: false` to `allowBuilds` (esbuild 0.28.2 is a dev dependency of the CLI; its postinstall only checks the binary).
