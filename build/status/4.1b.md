## Research notes
- oRPC OpenAPILink (contract-first, `JsonifiedClient`): https://orpc.dev/docs/openapi/client/openapi-link . The docs say `origin` may be omitted in a browser, but with `url: '/api'` 1.16.0 throws `"/api" cannot be parsed as a URL`; `api.ts` passes an absolute URL.
- MSW 3 WebSocket: `ws.link(url)`, `link.addEventListener('connection', ({client}) => ...)` returns a handler for `setupWorker`; `client.send`, `client.close(code)` accepts non-configurable codes such as 1006: https://mswjs.io/docs/api/ws . `worker.start({ onUnhandledFrame: 'bypass' })`: https://mswjs.io/docs/api/setup-worker/start . A WebSocket link needs no service worker (only REST does); both worked in WebKit.
- CSP: WebKit throws a synchronous `SecurityError` for a blocked WebSocket URL, Chromium fires an error event. `'self'` allows the same-host `ws:` in both, so the CSP is unchanged.

## Design questions
- **DQ-4.1a (signed path).** `signRequest` gets `path` as pathname plus query exactly as sent, including `/api`. DESIGN 8.10 says only `utf8(path)`. Proposal: the server signs/verifies `req.url` as received (query included, so GET inputs are authenticated). Tasks 4.2 and 3.7 must agree.
- **DQ-4.1b (state payload).** `WsServerMessage.payload` is opaque base64. The feed reads a `deal.state` row as UTF-8 JSON `{ "state": <DealState> }`. The contracts should type it (request to 1.2 / 3.7).
- **DQ-4.1c (nonce and ledger index).** `signRequest` returns the whole `ApiAuth`, so the vault owns the nonce and where the ledger index comes from. No contracts route returns the current validated ledger index; the web app needs one (request to contracts).
- For POST routes with path parameters, the body is the input minus the path parameters (oRPC compact encoding); the server must read `dealId` from the path.
