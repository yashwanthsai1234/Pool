## Design of the API
- `build<step>(input, { network, baseFeeDrops? })`: pure, never autofills, sets the minimum Fee (base, base x 5 for 4-of-4, `escrowFinishFee(base, fulfillmentBytes, 0)` = 350, one owner reserve for AccountDelete).
- `network` is `standalone | testnet | devnet`; `mainnet` or anything else throws. X-addresses throw (Mainnet `X` with its own message); addresses are checked with the contracts `XrplAddress` schema.
- `prepare(tx, { client, signers?, lastLedgerOffset?, feeMultiplier? })`: LastLedgerSequence = validated index + 20 (`LAST_LEDGER_OFFSET.single`) or + 1800 (`.collection`); Fee scaled by `feeMultiplier` (exits 5..10, max 10); then `client.autofill`.

## Research notes
- xrpl.js 5.3.0 `Client.autofill` fills only absent fields: a builder-set Fee/Sequence/LastLedgerSequence is kept; the 1.2x `feeCushion` applies only to a missing Fee (client/index.ts, sugar/getFeeXrp.ts). So the 1.2x margin never touches builder fees; headroom is explicit in `prepare`.
- xrpl.js `validate()` for CredentialCreate checks URI is hex and at most 256 hex chars (models/transactions/CredentialCreate.ts); CredentialType 1 to 64 (common.ts `validateCredentialType`); Memos shape (common.ts `isMemo`).
- NetworkID must not be set on Testnet/Devnet/standalone (autofill sets it only above 1024), so "wrong network" is a builder input check, not a field.
- Sources are in `packages/xrpl/SOURCES.md` (2.3 lines).
