## Design
- `FirmCosigner` is holder 2 of LA/LB. It reuses 3.9's `FrostHolder`, `cosignCheck`, `PgNonceLedger`, `RecoveryService`, key-list helpers and `registerAgentRoutes` (the recovery routes). New: `LawyerApprovals` (simplewebauthn assertion check + registered credential + single use + counter), `AuditLog` (hash-chained, trigger-protected), `FirmShareVault` (wrap key derived from `SignerPort`), operator authentication.
- Order of checks (all before a nonce is used): lawyer slot, operator signature over `tupleHash("legx/firm-cosign-request/v1", [deal, slot, session, seal, pair])` by the deal's ops account, share exists, seal equals the stored seal, deal state, recovery (only for pair 2+3), signer is a pinned console/partner, allow-list (`cosignCheck` with a no-approval role), WebAuthn approval, approval consumed. Then `releaseShare` (atomic mark) and an audit row.
- `cosignCheck` is called with role `console` so core's `cosign` skips its own sync approval check; the approval is checked by simplewebauthn instead.
- WebAuthn challenge = SHA-256 of the signed message (core's convention). A counter that does not advance maps to `APPROVAL_REUSED`.

## Design questions
- DQ-3.10-1: the wrap key is HKDF over a deterministic Ed25519 signature from `SignerPort` (it has no wrap or encrypt method). A KMS-backed port with `GenerateDataKey` would be cleaner.
- DQ-3.10-2: the recovery pair (2+3) still needs the lawyer's approval; if the lawyer lost the authenticator, a new credential must be registered first (no registration flow here).
- DQ-3.10-3: "transaction hash" in the audit row is the SHA-256 of the multisign message (an unsigned transaction has no ledger hash yet).

## Known gaps
- No HTTP route for signing or credential registration; signing is a library call (`FirmCosigner.sign`), as 3.9's ceremonies are. Only the lawyer-recovery routes are mounted via `register` (not tested over HTTP here; 3.9 tests them).
- Refresh and repair of the HSM share are not implemented (the agent has them).
- The audit sink is the evidence port (`frost.share.released`/`frost.refused`); wiring to the coordinator's signed log is the server composition's job.
- The audit row is written after the share is released; a crash between leaves a used nonce and no row.
