## Research notes (also `packages/db/SOURCES.md`)
- SKIP LOCKED is documented for queue-like tables: https://www.postgresql.org/docs/18/sql-select.html
- `uuidv7()` exists in PG 18, no strict monotonicity guarantee: https://www.postgresql.org/docs/18/functions-uuid.html
- PGlite `query` is single-statement with parameters; `exec` multi-statement without: https://pglite.dev/docs/api. Kysely 0.29 exports `Migrator` from `kysely/migration` (not the root).
- Kysely custom provider / dialect: https://kysely.dev/docs/migrations , https://kysely.dev/docs/recipes/dialects

## Deviations (evidence in the tests)
- No kysely-ctl and no testcontainers: own 30-line `.sql` provider on the Kysely Migrator; a fixed container (allowed by the task).
- PGlite dialect is my own (`src/pglite.ts`); a driver lock serialises the single connection.

## Design changes to record in DESIGN 9 (DESIGN.md is not mine)
- New tables `deal_head`, `used_nonce`, `frost_nonce_use` (append-only); `outbox.deal_id`, `outbox.seq` with index `(deal_id, seq)`.
- `deal.releaser_account` check uses `IS NOT DISTINCT FROM` (DESIGN's `=` passes when `lawyer_ops_b` is NULL).
- `deal_key`: `id_method` required for clients and NULL for lawyers; lawyers also require both `ops_bind_sig_*`. `bar_verification.status` limited to active/not_active.
- `enrollment_key` gains `deal_id` (FK), `valid_from`, `valid_to`, and `evidence_event_id` (NOT NULL FK to `evidence_event`, so a key with no evidence entry cannot exist; T-U-29). Unique on `(deal_id, slot, holder_role, ed25519_pub, mldsa65_pub)`; rotation is a new row.
- `attorney_credential` and `enrollment_key` are append-only (as the task says); `accept_tx_hash` therefore cannot be filled later by UPDATE.

## Design questions
- DQ-1: P3.1-12 says unique per (deal, role, holder) while P3.1-14 allows a second key for the same (slot, holder_role). Implemented: duplicate key pair refused, new keys allowed.
- DQ-2: `attorney_credential.accept_tx_hash` is nullable but the table is append-only, so the accept must be a second row.
- DQ-3: the first enrollment keys are pinned out of band, yet need an evidence event first; the event is signed by the pinned key (the DB does not verify signatures).

## Known gaps
- Gap-free seq is enforced by the repository (head row lock) plus UNIQUE(deal_id, seq), not by a DB trigger; a raw INSERT with a skipped seq is accepted.
- Owner and superuser bypass REVOKE; triggers stop them unless `session_replication_role = replica` is set (superuser only).
- `Repos` class constructors mention Kysely types in their `.d.ts`; method surfaces are plain. `@legx/db/pglite` returns a handle with an internal `kysely` field (test use).
- Not tested with a real LOGIN role (tests use SET ROLE app_rw).
