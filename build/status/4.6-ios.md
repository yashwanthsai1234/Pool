# 4.6-ios Native iOS chip reader

**State:** builds for device (`xcodebuild -sdk iphoneos CODE_SIGNING_ALLOWED=NO`: BUILD SUCCEEDED); 5 simulator tests pass. No real passport tried.

## Suite match (the key question)
CryptoKit in the iOS 26.4 SDK has `HPKE.Ciphersuite.XWingMLKEM768X25519_SHA256_AES_GCM_256` (X-Wing KEM, HKDF-SHA256, AES-256-GCM), the same as `@legx/core/pq` `hpke-xwing-v1`. Proved both ways with interop tests: CryptoKit opens a chip-link (@hpke) sealed bundle (info `legx/chip-link/v1`, aad = session||challenge, sk = 32-byte seed), and `tools/gen-vector.ts open` opens a CryptoKit sealed bundle in Node. No chip-link change needed. Limit: iOS 26+ only.

## Tests
- `xcodebuild -scheme ChipReader -destination 'platform=iOS Simulator,name=iPhone 17' test`: 5 passed (wire bytes equal Node's, QR parse, Node-sealed opens in Swift incl. wrong-aad fail, Swift-sealed opens in Node, MRZ check digit).
- Vector: `apps/chip-reader-ios/Tests/vector.json` from `tools/gen-vector.ts` (uses chip-link's real code).

## Research
- NFCPassportReader tag 2.3.3 (iOS 15+, OpenSSL-Package dep): `readPassport(mrzKey:tags:aaChallenge:skipCA:...)` takes a custom AA challenge; `activeAuthenticationSignature`, `getDataGroup(_).data` = whole file. Source read from a clone of the repo.
- CryptoKit X-Wing types read from the SDK swiftinterface (`XWingMLKEM768X25519`, `HPKE.Sender/Recipient`).
