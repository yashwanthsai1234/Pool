# 5.3b Differential (A/B) tests

State: done (P5.3-04/05 live Rust CLI not done, see Known gaps)

Tests: `pnpm vitest run --project unit tools/differential` : 5 files, 75 tests pass (about 80 s). Each test runs seeds 20261024 and 7
plus one random seed (printed in the test name; `LEGX_SEED=n` replays it). `LEGX_DIFF_N` sets the case count (default 10000).
`pnpm exec tsc -p tools/differential/tsconfig.json` and `pnpm exec biome check tools/differential` clean.

Results (no Python/TypeScript difference found, so nothing added to build/ISSUES.md):
- T-Z-02: 10,000 random transactions per seed from all 19 `@legx/xrpl` builders (random network, base fee, optional
  SigningPubKey/TxnSignature/Signers): xrpl.js `encode`, `encodeForSigning`, `encodeForMultiSigning` equal xrpl-py 5.2.0 byte for byte.
- P5.3-02: 10,000 cases per seed for each of 18 functions (tupleHash, 29-field dealSeal with refusals, domain, contractRoot,
  bindMsg, contractSigMsg, signedContractSeal, nftUri, mintMemo, opsBindMsg, presenceMsg, pqKeyHash, pqBindMsg, slotPolicy
  (roles shuffled for core), zk C_side, condition+fulfillment, gateMemo, mu). Refusals ("ERR": releaser != lawyerOpsB, 31-byte preimage) are compared too.
- P5.3-03 (each of 29 fields changes the seal, both agree), P5.3-08 (key order), P5.3-09 (salt/identifier byte flips): pass.
- P5.3-06: noble ml_dsa65 vs Node built-in, 200 random messages (0 to 2000 bytes) and contexts (0 to 255 bytes) per seed, both
  directions, plus wrong-context and changed-message rejection in both. Node derives the same public key from the same seed.
- P5.3-07: pqBindMsg signed by two holders in noble verifies in Node (and only under `legx/pq-binding/v1`, only under that holder's key).
- P5.3-10: Python mu (`mldsa_mu` in legx_ref.py) equals `muFor`; noble `internal.sign(mu, externalMu)` over it verifies in Node and noble with the context.
- FROST: ZF vectors.json and vectors-big-identifier.json replay byte for byte through noble (nonce commitments, signature shares,
  signature) and verify in Node's OpenSSL Ed25519; then 100 random messages and signer subsets per seed, each share verified, aggregate verified in noble (strict) and Node, tampered message rejected.

Research notes: Node 24.22.1 `crypto.sign(null, msg, {key, context})` supports ML-DSA-65 and JWK `{kty:'AKP', alg:'ML-DSA-65', pub, priv(seed)}`
(sandbox check; https://nodejs.org/api/crypto.html). noble 0.7.1 `internal.sign(mu, sk, {externalMu:true})` takes a 64-byte mu.
