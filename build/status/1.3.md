## Module cycle (item 3)
Evidence (commands in `build/tmp/1.3/cyc/`, run from `packages/core`):
- Node 22.14.0 (`/usr/local/bin/node`): `import { Wallet } from 'xrpl'; import { ed25519 } from '@noble/curves/ed25519.js'` fails with `ERR_REQUIRE_CYCLE_MODULE: Cannot require() ES Module .../@noble/hashes/utils.js in a cycle (from @xrplf/isomorphic/dist/utils/shared.js)`. Noble imported first works.
- Node 24.22.1: both orders work, and a probe importing every Appendix module plus xrpl and noble works. Regression test: `test/cycle.test.ts`.
- With `--no-experimental-require-module` xrpl fails on Node 24 too (`ERR_REQUIRE_ESM`): xrpl needs `require(esm)`.
- Conclusion: not a problem on Node 24.22 (the pinned engine). If Node 22 is ever needed, importing noble before xrpl avoids it (what `dealcore.ts` does). I found no Node changelog entry naming the fix; the web search turned up only downstream issues (nodejs/node restricts cycles through `require(esm)` on purpose). Source: https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require.
