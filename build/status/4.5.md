## Design questions
- DQ-4.5-1: the live feed row shapes the dashboard needs are not in contracts. It reads OD-9 (`deal.event` = `{envelope, summary}`; statement `predicate.data`), `ledger.observation` rows as the watcher writes them (`{hash, ledger_index, account, tx_type}`) for the lock steps, `lock.verified.findings`, `release.gate.passed.gate.findings`, `frost.signed.{slot, signer_key_ids}`, `checkpoint.anchored`. Lock steps follow the transaction types of DESIGN 5.2 5a to 5g in order (SignerListSet, AccountSet, AccountSet, DepositPreauth, CredentialCreate, CredentialAccept, AccountSet); an out-of-order type does not pass a step.
- DQ-4.5-2: the live socket needs a signed upgrade (3.7 `canRead`). The projector has no enrollment key. A read-only dashboard principal (or a demo-profile unsigned read) is needed before the dashboard can connect to the real server. Until then it is tested against the MSW socket.
- DQ-4.5-3: `ledger.observation` rows have no `deal_id` in 3.5, so a per-deal subscription may never receive them (I-3.7-h territory).

## Known gaps
- Each scene run opens its own `ControlledChain` and runs a full deal (5 to 7 s for the ledger scenes), so a button takes several seconds; the button shows "Running...".
- The attack routes are unsigned (demo only, behind the demo hook). Scenes run on a separate funded set of accounts on the standalone ledger, not on the demo deal, so "double exit" and "master key" do not touch the deal the room is watching; the attack result is overlaid on the dashboard instead.
- `bundle-byte` flips one bit in the middle of the zip, which the zip CRC catches before the signature checks run (`FAIL:archive`). A flip inside a stored signature or hash is covered by tools/verifier-cli tests.
- Screenshot baselines are per machine and browser (`-darwin`); CI on another OS needs its own.
- WebKit has no CDP, so the emulated reduced-motion run is Chromium only.
- Not tested: the real dashboard against the real server over a tunnel; the production CSP with a live feed (only the waiting screen is in the build test).
