## Design of the role script (`test-int/roles.ts`, reusable by E2E-P3 and SYS-01)
- `openChain()`: ledger connection, background closer, `send`, `multisend` (4 FROST slots then `combine`), `step(name, fn)` (a failure reads `[P5 step 5c ...] ...`), per-transaction log.
- Roles: `makeSlot(name)` (DKG, enrollment keys, ML-DSA keys, DKG record, `sign`, `signTx`, `holderSigner`), `makeClient(side)`, `makeLawyer(role, firm, curve, bar)`, `withSlot`, `makeVerifier()`.
- Records: `evidenceFor(dealId, root)`, `barVerification`, `barDealLink`, `opsBoundData`, `pqBoundData`, `onboardingRecord`, `passportRecordAt` (chip checks from `chipChecks` on `@legx/fixtures` passports, Active Authentication bound to `presenceMsg`), `dealData`.
- Ledger input: `readGateLedger` (`snapshot` of the wallet and both ops accounts at one validated ledger; the mint by hash in binary and decoded form).

## Deviations and decisions (read these)
1. **Chip identity, not ZK.** The task message asked for ZK onboarding from recorded fixtures with the replay adapter. IMPLEMENTATION 2.5 says chip fixtures (`identityPolicy: "chip"`, ZK is T-I-12 in 2.9), and P2.5-04 says `profile: "production"`. The production profile refuses the recorded mock proofs (`DEVMODE_REFUSED`), so a ZK flow cannot pass a production gate. I followed IMPLEMENTATION. Issue I-2.5-f.
2. **The verifier service is not run.** Steps 0a and 0b use the `@legx/xrpl` builders (`build0a`, `build0b`) and the verifier's hybrid-signed `BarVerification` and `BarDealLink` records are made in the script. The service itself needs Postgres and is covered by 3.3's own integration test.
3. **Replacement hands over the release code.** The escrow condition is fixed by Alice's `EscrowCreate`, so the old lawyer B's preimage passes to the new lawyer B in the script (I-2.5-e).
4. `happy.int.test.ts` is removed (replaced by T-I-01). `scripts/extract-harness.ts` would regenerate it (I-2.5-a). `test-int/harness.ts` stays because `ledger.int.test.ts` uses it.
5. Added dependencies to `packages/xrpl` through `scripts/pnpm-safe`: `@legx/fixtures` (workspace), `@noble/curves` 2.4.0, `@noble/hashes` 2.4.0. The test imports `packages/core/test/helpers/frost.ts` by relative path (as 2.4 does).
6. Test file is named `full-flow.int.test.ts` (the plan said `full-flow.int.ts`; the integration glob needs `.int.test.ts`). T-I-10 lives in the same file as asked.
