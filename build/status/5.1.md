## Deviation (evidence)

- **T-F-01b at 30 steps.** A full Apalache bounded check at 30 steps is out of reach: it took 139 s at 8 steps and 771 s at 10 steps. Instead, `spec/check.sh apalache` checks 10 steps from `init` and from `initFunded`, and `apalache-sim` covers 30 steps by symbolic simulation, at about 20 s per run. Logs are in `build/tmp/5.1/apa-*.log`.
- **Liveness bound.** With `LIVE_FAULTS = 1` the state space is 823k states. With 2 faults it passed 7 million distinct states after 12 minutes (`build/tmp/5.1/tlc-live-f2.log`), so I stopped it.
- **`pnpm-workspace.yaml` (outside my folder).** `pnpm add` of Quint failed with `ERR_PNPM_IGNORED_BUILDS` for `protobufjs@7.6.6`. That package's postinstall script only prints a version warning. This would have broken every `pnpm install --frozen-lockfile`. I ran `scripts/pnpm-safe approve-builds '!protobufjs'`, which added `allowBuilds: { protobufjs: false }`. The install then passes. The file before the change is saved at `build/tmp/5.1/pnpm-workspace.before.yaml`.

## Research notes

- Quint 0.33.0 is the latest version, published 2026-09-28, so it is older than 3 days. Source: `pnpm view @informalsystems/quint time`.
- CLI flags (`run --max-steps/--max-samples/--n-traces/--out-itf/--witnesses/--init/--step`, `verify --backend tlc --temporal --tlc-config --random-transitions --apalache-config`): https://quint.sh/docs/quint. They match `quint run --help` and `quint verify --help` for 0.33.0.
- Apalache is the default backend. It is downloaded automatically, to `~/.quint/apalache-dist-0.62.1`, which takes 192 MB. The Rust evaluator takes 2.3 MB. Both need Java 17 or later; Java 24 works. Source: https://quint.sh/docs/model-checkers
- TLC runs as `tlc2.TLC` from the Apalache jar with `-deadlock`. The generated `.cfg` has only INIT, NEXT, INVARIANT and PROPERTY, so fairness must go inside the temporal formula. Source: https://github.com/quint-co/quint/blob/main/quint/src/tlc.ts
- Apalache runs as a server on port 8822 and writes `_apalache-out/` into the working directory. Two `verify` commands at the same time share that server, and the first to finish kills it ("Connection dropped" in my logs). Run them one at a time.
- Apalache reports a terminal state as a deadlock, so I added `closedStays`. Source: https://apalache-mc.org/docs/apalache/running.html
- The simulator picks uniformly among the enabled `any` branches. I checked this with a sandbox model in `build/tmp/5.1/weight.qnt`. Hence the weighted `stepSim`.
- ITF format: https://apalache-mc.org/docs/adr/015adr-trace.html. Sum types appear as `{tag, value}`.

## Design questions

- **DQ (I8 is enforced by the console, not the ledger).** The ledger cannot see the release gate. A lawyer B who holds the code can send `EscrowFinish` from the preauthorized account without running the gate. The model treats the console as trusted, and D4 limits the harm. Should DESIGN 5.1 say I8 is a console rule?
- **DQ-6 confirmed in the model.** With two shares of one slot lost, recovery cannot sign, so the money never leaves `FUNDED`/`DISPUTED`. `twoSharesLostTest` shows this. The `endsDQ6` TLC check is set up in `check.sh tlc` but was not run within the time box.
